# BC Arcade — Store Submission Game Plan (target: submit by Oct 15, 2026)

## Context

BC Arcade v1.0.9 (build 10009) has never been submitted to either store. Epic #1916 (first-submission readiness) and epic #821 (productionization) track the gaps. The goal: **submit to both the Apple App Store and Google Play by Oct 15**, working day-by-day from Sep 18 with two machines (1 Mac, 1 PC) available every day.

### Decisions made (with the user, 2026-09-17)

1. **Premium games are hidden entirely in v1.0** — not shown locked, not free. The 6 premium games (~~yacht~~ **blackjack**, cascade, hearts, sudoku, starswarm, sort) disappear from the store build; the 6 free games ship (~~blackjack~~ **yacht**, solitaire, freecell, mahjong, daily word, twenty48). **Amended 2026-09-23 (owner): Blackjack and Yacht swapped tiers** — Blackjack is simulated gambling, which would rate the whole app Apple 13+/18+ and PEGI 18; Yacht (dice, no gambling) keeps v1.0 at 4+ / Everyone / PEGI 3. Backend: migration `0020_swap_yacht_blackjack` flips `game_types.is_premium`; daily challenge free pool gains score-based Yacht goals, Blackjack's wait for #2458 (see `docs/STORE-LISTING.md` §1). IAP comes post-launch (epic #822). This resolves blocker #1917 without building IAP and without ever releasing premium content free. **Amended 2026-09-19 (owner): all 12 games stay visible and free in pre-launch builds.** A build compiled against the pre-launch (dev) API — internal TestFlight / Play test builds and the `dev`-branch staging site — shows every game, and the dev backend already grants every premium game to every session (`ENTITLEMENT_DEV_OVERRIDE`). A build compiled against anything else is a store build and hides the six. **There is no flag to flip back before launch**: pointing the release config at the production API (Tue 29) hides the games and ends the free entitlements in one step (#2417, `ARCHITECTURE.md` §10.7). Nothing premium is ever free in a store build.
2. **Guideline 4.2 mitigation = XP + daily challenge** (#1914 Tier 1 minus Game Center): server-side Arcade XP/player level, one daily cross-game challenge over free games, home-screen progression, strong reviewer notes.
3. **Store accounts + app records already exist** in App Store Connect and Play Console; app has been on internal/closed testing before. No Play 14-day cold-start blocker assumed (verify Day 1).
4. **Quality bar for launch = crash/stability fixes only.** i18n gaps, a11y backlog, and CI hardening are explicitly deferred post-launch (except where a hidden game makes the issue moot).
5. **Production database = Supabase; dev database stays on Render; local + CI stay on SQLite** (owner, 2026-09-20). Supabase is prod-only — nothing else points at it. **It is a fresh database, not a migration**: prod has never existed, so nothing is copied from dev (no test scores, XP or dev-override entitlements in launch-day data); `alembic upgrade head` builds the schema and every seed row. Supabase runs on the **free plan through setup and QA, and moves to Pro before the Oct 9 submission** (free projects pause after ~7 idle days and have no backups). **Sentry keeps one project per platform and splits dev from prod by the `environment` tag** — no separate prod DSN. Design in section D.

## Feature designs (from code investigation)

### A. Hide premium games (~1.5–2 dev-days)

**Mechanism: compiled TS constant, NOT an env var and NOT server-driven.** Two reasons: (1) Apple 2.3.1 — the reviewed binary must equal what users get; a server flag that unhides content post-review is itself a rejection pattern; (2) **`frontend/ios/ci_scripts/ci_post_clone.sh` deletes `.env.production` and force-writes a 2-line `.env` on every Xcode Cloud build** — any new `EXPO_PUBLIC_*` var silently disappears, which could ship premium games to App Review by accident.

- New file `frontend/src/entitlements/gameVisibility.ts`: `HIDDEN_GAMES` set (the 6 premium slugs), `SHOW_HIDDEN_GAMES = __DEV__ || process.env.EXPO_PUBLIC_TEST_HOOKS === "1"` (reuses the existing test-build signal already set by the Maestro/Playwright test builds and used in `httpClient.ts`/`syncApi.ts`), `isGameVisible(slug)`. Keep visibility decoupled from `PREMIUM_GAMES` in `EntitlementContext.tsx` (unchanged — IAP re-activates it later).
- `frontend/src/screens/HomeScreen.tsx`: the 12-game array is a hardcoded literal (backend catalog is never fetched — leave it that way); rename to `ALL_GAMES` and filter through `isGameVisible`.
- `frontend/App.tsx`: conditionally register hidden games' screens in `LobbyStack()`; keep `makePremiumScreen()`/`LockedGameScreen` (still correct for dev/test builds). **Also hide the "Ranks" tab in `MainTabs()`** — `LeaderboardScreen.tsx` is StarSwarm-only, a dead tab once StarSwarm is hidden.
- Backend: **no change** (leave `is_active`/`is_premium` rows alone; `is_active=False` would break `POST /games` for internal testing).
- Maestro: **no work** (descoped 2026-09-18). Existing premium-game flows are unaffected because test builds set `EXPO_PUBLIC_TEST_HOOKS=1`; the `navigation.yaml` switch, the `home/hidden-games.yaml` negative flow, and the no-test-hooks CI job are dropped.
- Jest (now the only automated guard): verify `HomeScreen.test.tsx` behavior under Jest's `__DEV__`; add hidden-games describe block (copy the existing "Pachisi disabled" pattern) + `gameVisibility.test.ts`, which must assert all 6 premium slugs are hidden with `__DEV__ === false` and `EXPO_PUBLIC_TEST_HOOKS` unset.

## Model + token usage policy

- **Sub-agents:** `haiku` for mechanical work (exploration, lint fixes, translation file passes, doc drafting, issue filing bodies, per-game `CLAUDE.md` drafts); `sonnet` for code-implementation subagents and the four algorithm-heavy game write-ups (section E); main session drives design, review and orchestration. Never opus subagents without written justification (global cost rule).
- **Infra over MCP (Render / Supabase / Sentry) is done by the main session, never a subagent** — a handful of calls, high stakes, and it needs the whole plan in context.
- **Call by ID, never list.** Resource IDs are recorded in "Current ground truth": use `get_service` / `get_postgres` / `get_project`. `list_services` returns all 13 services in the workspace (~5k tokens per call). Supabase `list_tables` with `verbose: false`; `list_logs` / `query_logs` only while debugging, tightly filtered.
- **Secrets never enter a Claude session** — not in chat, not as an MCP tool argument, not in a file Claude reads. The owner pastes them into dashboards or exports them in their own shell. This repo is public.
- **Don't delegate what is already in context.** Editing this plan is main-session work (one file, already loaded); spawning an agent means paying to re-read it.
- **Reviews:** one `/code-review medium` pass per code PR; docs-only PRs get none.
