# CI Checks and Branch Protection

Every PR into `dev` or `main` shows close to 40 checks. This guide says what each one is for, what it prevents, where it is defined, when it was introduced, how it gates, and roughly how long it takes. Research issue: #3103. Making the colour-literal and docs-link checks required is tracked in #3102.

Source of truth is `.github/workflows/`; this document is a snapshot taken from `dev` at `8f6a834a` (2026-10-09), updated for the job consolidation in #3113 (see [Job consolidation (#3113)](#job-consolidation-3113)). If it disagrees with the workflow files, the workflow files win. For how the test layers fit together see [TESTING.md](TESTING.md); for the native build pipelines see [IOS.md](IOS.md) and [ANDROID-CI.md](ANDROID-CI.md).

## Summary

A PR into `dev` or `main` triggers 38 workflow jobs (43 before #3113): 32 in `ci.yml` plus 6 jobs in 5 stand-alone policy and hygiene workflows (`commitlint`, `design-token-check`, `openai-policy`, `gemini-policy`, `schema-migration`, which has a small `python-version` job ahead of `schema-check`). Many of these call reusable workflows from the org repo `wcmchenry3-stack/.github`. Seven checks are conditional: `ios-build-check`, `android-build-check` and `Podfile.lock freshness` (native changes; the first two always run on PRs into `main`), `android-release-smoke` (Android-relevant files), the Playwright E2E scope (selective on `dev`, full suite on `main`), and the Yacht and Hearts sim gates (AI paths only, up to 90 minutes). The slowest unconditional checks are Playwright E2E (about 13 minutes on a full run), `test-python` (about 6 minutes) and `test-frontend` (about 4 minutes); everything else finishes in under a minute.

Not covered by workflow files, and so not described in detail here: CodeQL, Supabase Preview and the Codex review app (see [External apps](#external-apps-not-in-workflow-files)).

### How to read the tables

- **Introduced**: the earliest commit that adds the job to the workflow file (`git log -S`), with the PR or issue number from the commit subject when it has one. Early commits have no number; those are cited by short SHA. The five stand-alone workflows were synced from the org template into this repo on 2026-04-11; their real origin is in the org repo and is "origin unclear" from here.
- **Gating**: "Always" means the job runs on every PR into `dev` and `main`. "Tier 1" means it has `needs: [lint-python, lint-frontend, secret-scan, repo-hygiene]`, so it is skipped when any of those Tier 0 jobs fails.
- **Time**: wall-clock for the job on a recent successful run of `ci.yml` (run 37901059505, 2026-10-09). For checks that are now steps of a merged job (#3113), the figure is what the former stand-alone job took, setup included. A figure marked "timeout" is the configured limit, not a measurement. Runner start-up and queueing are not included.
- **Reusable workflow bodies** live in `wcmchenry3-stack/.github`, which is not readable from this repository. Where a purpose below is taken only from the job name or its inputs, the cell says so.
- A check named `Repo hygiene › X` or `Frontend static checks › X` is step `X` of that merged job (#3113). The PR checks list shows only the job name; open the job to see which step failed.
- Where a reusable workflow is called, the check shows up in GitHub as `<job> / <inner job name>` (for example `lint-python / Lint Python (black + ruff)`). Branch protection matches on that full string.

## Tier model in `ci.yml`

```text
Tier 0 (start immediately)
  gate-main-source, secret-scan, lint-python, lint-python-tools, test-tools,
  lint-frontend, repo-hygiene
        |
        v   needs: lint-python, lint-frontend, secret-scan, repo-hygiene
Tier 1  everything else except the four below
        |
        v   needs: test-python, test-frontend (+ detect-* where noted)
Tier 2  e2e (also needs detect-e2e-scope), ios-build-check, android-build-check,
        android-release-smoke
Podfile.lock freshness needs only detect-native-changes.
```

`gate-main-source`, `lint-python-tools` and `test-tools` are Tier 0 but are not in the Tier 1 `needs:` list, so a failure in them does not skip the Tier 1 jobs.

### Recommended required checks

These are recommendations, not a record of current settings. Two rules of thumb: a conditional job that is skipped counts as passing for required-check purposes, so conditional build checks can safely be required; and a required check must exist on every PR, so required names should come from jobs that always start. Use the exact check names as shown in the PR (for reusable workflows, `<job> / <inner job>`).

**`dev`** (fast, deterministic, always-on). Names are the exact check-run names as GitHub shows them on a PR:

- `gate-main-source / Verify PR source is dev`, `secret-scan / Secret scan (gitleaks)`, `lint-python / Lint Python (black + ruff)`, `lint-frontend / Lint frontend (eslint + prettier)`, `Repo hygiene` (conflict markers, forbidden terms, large files), `commitlint / Lint PR title`
- `Frontend static checks` (type-check, knip, knip --production, i18n, colour literals), `test-python / Test Python (pytest)`, `test-frontend / Test frontend (jest/vitest)`, `Playwright E2E`, `schema-check / Schema migration check`
- `cve-python / CVE scan Python (pip-audit)`, `cve-frontend / CVE scan frontend (npm audit)`
- `design-token-check / Design Tokens & Accessibility Check`, `openai-policy-check / OpenAI API Policy Check`, `gemini-policy-check / Gemini API Policy Check`
- `Markdown links (lychee, offline)` (with the colour-literal check, now inside `Frontend static checks`, the subject of #3102)
- `Backend file length (per-file caps, default 800)`, `local-path-check / Local Path Detection`, `android-bundle-check`
- `ios-build-check`, `android-build-check`, `Podfile.lock freshness`, `android-release-smoke` (safe to require because they skip when not applicable)

Check-run names change if a job's `name:` changes, so re-copy them from a recent PR's checks list when applying this. Leave advisory for now: `sentry-cli-check` (fails on a bad token, but that is an org-secret problem unrelated to the PR, so keep it advisory), `backend-health / Backend Health` (depends on the live dev Render service), `Duplication (jscpd)` (a threshold that can trip on unrelated PRs), `Test tools (pytest)` and `lint-python-tools / Lint Python (black + ruff)` (only meaningful when `tools/` changes), and the sim gates (path-conditional; if required they must be required on the conditional path only).

**`main`**: everything above, plus the checks that are skipped on `dev`: `ios-build-check` and `android-build-check` become real builds on every release PR, and `Playwright E2E` is the full suite. `gate-main-source` is the check that matters most on `main`.

## Job consolidation (#3113)

Cheap jobs that each booted a runner for a few seconds were merged so the checks list is shorter and fewer runners start per run. Every former check is now a named step of the merged job. Each check step runs even if an earlier step failed (`if: !cancelled()` plus a check that checkout or setup succeeded), so one run reports every failing check, not just the first.

**Job count.** PR jobs: 43 before, 38 after. `ci.yml`: 37 before, 32 after. Seven former jobs became steps of two new jobs.

| Former check (job id)                                          | Now                                                                                                              | Gating change                                                                                                                                   |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `Conflict marker check` (`conflict-markers`)                   | `Repo hygiene` (`repo-hygiene`), step `Conflict marker check`                                                    | None: still Tier 0 and in the Tier 1 `needs:`                                                                                                   |
| `Forbidden brand/trademark terms` (`forbidden-terms`)          | `Repo hygiene`, step `Forbidden brand/trademark terms`                                                           | None: still Tier 0 and in the Tier 1 `needs:`                                                                                                   |
| `Large tracked file guard (over 5 MiB)` (`large-file-guard`)   | `Repo hygiene`, step `Large tracked file guard (over 5 MiB)`                                                     | Moves from Tier 1 to Tier 0. It no longer waits for the lint jobs, and a too-large file now also skips the Tier 1 jobs (stricter, never looser) |
| `typecheck-frontend` (`typecheck-frontend`)                    | `Frontend static checks` (`frontend-static`), step `TypeScript type-check`                                       | None: Tier 1                                                                                                                                    |
| `Unused code (knip)` (`knip`)                                  | `Frontend static checks`, step `Unused code (knip)`                                                              | None: Tier 1, blocking                                                                                                                          |
| `i18n completeness check` (`check-i18n`)                       | `Frontend static checks`, step `i18n completeness check`                                                         | None: Tier 1                                                                                                                                    |
| `Colour literals (per-game palettes)` (`check-color-literals`) | `Frontend static checks`, steps `Colour literals (per-game palettes, #2989)` and `Colour literals checker tests` | None: Tier 1                                                                                                                                    |

`needs:` changes: every Tier 1 job's `needs: [lint-python, lint-frontend, secret-scan, conflict-markers, forbidden-terms]` became `needs: [lint-python, lint-frontend, secret-scan, repo-hygiene]`. Tier 2 `needs:` are unchanged. No `if:`, `continue-on-error`, `permissions:` or `env:` setting changed: none of the merged jobs had any of them, so the merged jobs run with the workflow default `contents: read`.

**Runner time (estimate).** From the timings above: the three hygiene jobs took 27 s of job time, and the merged job does one checkout plus three greps and a stdlib script, about 12 s. The four frontend jobs took 165 s, each paying about 35 s for checkout and `npm ci`; the merged job pays that once, about 75 s in all. That is about 105 s less job time per CI run, plus five fewer runner start-ups (not included in the timings, typically 10 to 30 s each). If minutes are billed per job rounded up to the minute, the seven jobs bill 7 minutes and the two merged jobs about 3, so about 4 billed minutes saved per run. Wall-clock is unchanged: Tier 1 is bound by `test-python` (about 6 minutes), and both merged jobs finish well inside that.

**Considered and not changed:**

- **`lint-python` and `lint-python-tools`.** Both call the org `called-lint-python.yml`, so they cannot be two steps of one job without changing the org workflow, which is not readable or editable from here. A matrix over `working-directory` is possible, but each matrix leg is still its own reusable-workflow run and its own check, so it saves no runner time and no check names. It would also make `lint-python-tools` a Tier 1 gate (a matrix job in `needs:` waits for every leg), which this document recommends against. Left as two jobs.
- **`expo-compat`.** Static, same tier, but its result depends on Expo's remote compat matrix, which moves on its own; inside a required job a drift there would block the type-check, knip, i18n and colour-literal checks. Left separate.
- **`sentry-cli-check`.** Runs on PRs only (`if: github.event_name == 'pull_request'`), unlike the merged checks, and needs the Sentry token. Left separate.
- **`android-bundle-check`, `test-frontend`, `Playwright E2E`.** Runtime-heavy, and `android-bundle-check` needs `pull-requests: write` for its comment. Left separate.
- **Org `design-token-check` versus local `Colour literals`.** The org workflow body (`called-design-token-check.yml`) is not readable from this repository, so it is not possible to tell from here whether it still catches anything the local check does not (it also covers px font sizes and positive `tabindex`, per `.claude/policies/design-tokens.md`). Not retired. **Needs an owner check** in `wcmchenry3-stack/.github` before it is removed.

## Observations (suggestions only)

These are not decisions.

- **`lint-python` and `lint-python-tools`** call the same reusable workflow with different directories and the same ruff pin. Left separate in #3113; see [Job consolidation](#job-consolidation-3113) for why.
- **Done in #3113:** the three "cheap grep" jobs are now the `Repo hygiene` job, and typecheck, knip, i18n and colour literals are now the `Frontend static checks` job.
- **Frontend jobs that still repeat the `setup-frontend` install**: `Frontend static checks`, `expo-compat`, `sentry-cli-check`, `android-bundle-check` and `Playwright E2E` (plus `android-release-smoke` when it builds). See [Job consolidation](#job-consolidation-3113) for why these stay separate.
- **Policy workflows**: `design-token-check`, `Colour literals` and `lint-frontend` overlap in intent (hard-coded styling). The org design-token check is policy-based; the colour-literal checker is repo-specific and stricter about per-game palettes. Not retired in #3113: the org workflow body is not readable from here, so whether it still catches anything the local check does not **needs an owner check** in `wcmchenry3-stack/.github`.
- **`Gemini policy`** passes trivially today but is intentionally kept (see the file comment). Do not treat it as a consolidation candidate without a policy decision.
- **Resolved in #3111:** `Unused code (knip)` is now a real gate. `gradle-wrapper-check` fails only on wrapper validation; its second step is labelled "(advisory)". `sentry-cli-check` fails on a bad token and warns only when the secret is unset. No check names changed.
- **`backend-health`** probes a live external service and can fail for reasons unrelated to the PR.
- **Expensive checks**: `Playwright E2E` (about 13 minutes, full suite on every `main` PR and any shared-path change), `test-python` (about 6 minutes), `test-frontend` (about 4 minutes), and the native build checks. A full suite is wall-clock bound by test-python or test-frontend followed by E2E, about 20 to 25 minutes end to end on recent runs. Everything else is under a minute.
- **Cancelled runs**: the `ci.yml` concurrency group cancels superseded runs on PR branches, which is why the checks list can show earlier cancelled attempts.
- **`Supabase Preview`** always skips because Supabase branching isn't enabled. Supabase stays the production database (#3112); only its GitHub integration is unused, and disconnecting it would just remove this skipped check.
- **Reusable workflows are in another repo.** Several checks (`provenance-coverage`, `feedback-token-lint`, `sentry-check`, `gate-main-source`) cannot be explained from this repo alone. A short description in each `called-*.yml` header, or a link from here, would close that gap.
