# Decision record: public leaderboard identities (#2778)

- **Status:** Accepted for v1.0 (owner decision, 2026-09-30).
- **Issue:** [#2778](https://github.com/wcmchenry3-stack/BC-Arcade/issues/2778), part of [#2777](https://github.com/wcmchenry3-stack/BC-Arcade/issues/2777).
- **Referenced by:** #2779 (privacy policy and store privacy declarations), #2780, #2784.
- **Supersedes:** the typed-name model of #2502, #2519 (decisions 17–18), #2624 and #2637, which let a player type any 1–32 characters as their public name.

## Decision

Public leaderboard names are **generated by the server and cannot be edited as text.**

- Joining the leaderboards is an **explicit opt-in**: the player presses **Join leaderboards** (Profile, or the one-time prompt on a result card).
- On joining, the server assigns a name of the form **`Adjective Animal N`**, for example "Brave Otter 4821". The two words come from short, curated lists (`backend/players/generated.py`); the number is 10–9999. Names are the same English words on every locale. They are not unique: a board identifies a player by their player id, not by their name.
- The player can **Get a new name** (another generated name) or **Leave leaderboards** at any time. Leaving removes their name and takes every entry of theirs off every board. Joining again gives a new generated name.
- A player who has not joined appears on **no** board. Anonymous play remains fully supported.

We did **not** choose editable names. Editable public text would have needed user-generated-content terms, consent before posting, filtering, in-app reporting and blocking, and an ongoing moderation process. Generated names avoid abusive public text without any of that.

## Enforcement: client and API

- **API.** `PUT /players/me` joins the boards and takes **no body**; any `display_name` a client sends is ignored and never stored. `POST /players/me/reroll` swaps the name for another generated one (404 when the player has not joined, so a reroll never opts anyone in). `DELETE /players/me` leaves. `GET /players/me` returns the generated name or `null`. The only code that writes `players.display_name` is the server's generator (`players/service.py`) and migration 0030.
- **Older builds.** A build from before #2624 may still send a typed `player_name` in `POST /games` metadata. Under the model those builds use, typing a name _was_ the choice to appear on the boards, so the server keeps that choice. It joins the player under a generated name and never stores the typed text as their public name. A current build sends no name text at all.
- **Client.** The app has no name text field. Profile shows the generated name with **Get a new name** and **Leave leaderboards**, or a **Join leaderboards** button. The result card's one-time prompt is a **Join leaderboards** button.

## Existing players (migration 0030)

Alembic migration `0030_generated_player_names` rewrites every existing `players` row:

- **Players who had a name stay on the boards, under a generated name.** Under the old model, a `players` row existed only because the player deliberately set a name. They typed it in Profile, in the result card's one-time prompt, or in an older build's win modal (backfilled by migration 0027). Setting a name was that model's opt-in, so their opted-in status is kept. Their typed text is replaced by a freshly generated name and is not kept anywhere by the migration.
- **Nobody else is opted in.** Players without a row, who never set a name, get no row and stay off every board until they press **Join leaderboards**. The migration never creates rows.
- On the device, the app refreshes its copy of the name from `GET /players/me` at launch and when Profile opens, so a migrated player sees their generated name, not the old typed one. A name typed on the device before #2624 and never sent to the server becomes a join, under a generated name, on the next launch. That is the same rule as above.
- Downgrade is a no-op, because the typed names cannot be restored.

## Removal and erasure (unchanged)

- **Profile → Leave leaderboards** sends `DELETE /players/me` through the app's offline-safe one-slot sync. An offline leave goes out on reconnect.
- **Settings → Delete my data** (`DELETE /me`) erases the player's name along with the rest of their data.

## Notes for privacy and store declarations (#2779)

These facts are for #2779. This PR does not edit `privacy-policy.html` or `STORE-PRIVACY-ANSWERS.md`.

- The public leaderboard shows a **server-generated pseudonym**, the player's scores, and completion dates. It never shows text the player typed.
- Participation is **opt-in** and can be withdrawn at any time (leave), or erased entirely (Delete my data).
- The player is identified by a random per-install id (`X-Session-ID`). There are no accounts.
- **Residual typed text:** games created by builds from before #2624 may still hold a `metadata.player_name` on the player's own `games` rows. It is private to that player's session, is never shown on a board, and is erased by Delete my data. #2779 may decide whether to scrub it proactively.

## Out of scope

- Accounts and cross-device identity (#1047, #144). A future account can carry the generated name over, but that design is not part of this decision.
